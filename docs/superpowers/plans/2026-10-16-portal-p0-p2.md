# Portal P0–P2 Implementation Plan

> **For agentic workers:** executed natively in one session (superpowers:executing-plans). Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Foundations (host split, mailer, verification), the `packages/ui` extraction, and a portal
skeleton (second process, second Better Auth instance, `apps/portal` shell) — spec §15 P0–P2.

**Architecture:** One repo, one image, two Bun processes (`apps/server/src/index.ts`,
`apps/server/src/portal/index.ts`) sharing Postgres and the `user`/`account`/`verification` tables;
two SPAs (`apps/web`, `apps/portal`) sharing `packages/ui`. Sibling cookie zones
(`.app.<domain>`, `.portal.<domain>`) so neither session cookie reaches the other process.

**Tech Stack:** Bun, Hono, oRPC, Better Auth 1.7.7, Drizzle/Postgres, React 19 + UI5 Web
Components + TanStack Router/Query, Resend + React Email (`react-email` — `@react-email/components`
is deprecated).

**Spec:** `docs/superpowers/specs/2026-10-07-portal-redesign.md`

## Global Constraints

- Dev hosts: `app.lvh.me` (internal, Vite :5173, server :3000) and `portal.lvh.me` (portal, Vite
  :5174, server :3001). Prod: `APP_BASE_DOMAIN=app.confire.ai`, `PORTAL_BASE_DOMAIN=portal.confire.ai`.
- `tenant.ts` stays the only place a host is parsed; the portal passes its own base domain.
- No dev/prod branch in code: `RESEND_API_KEY` unset → console mailer; that is config, not a branch.
- Sender `notify@<MAIL_DOMAIN>` (`mail.<domain>`), display name quoted.
- Portal session table `portal_session`, export key `portalSession`; cookie prefix `confire-portal`.
- Captcha: Turnstile on `/sign-up/email`, `/sign-in/email`, `/request-password-reset` (portal only).
- Templates take one typed props object per event (§17).
- Decided with the user 2026-10-16: no grandfathering (unverified users verify on next sign-in,
  `sendOnSignIn`); forgot/reset pages in both apps; P2 branding = `organization.name`/`logo` only.
- Per-project typecheck: `packages/{b1,config-engine,db,ui}`, `apps/{agent,server,web,portal}`.

## Review Focus

1. An unverified password user signs in → 403 + a fresh link, not a dead end (test in Task 2).
2. A portal session cookie never authenticates an internal request and vice versa (Task 7).
3. An internal member of the host tenant is refused by every portal builder (Task 7).
4. `packages/ui` keeps the oRPC query keys, so `QuoteCreatePage`'s cache seed and `$entity`'s
   metadata refresh still land (Task 4: keys come from the app's own `orpc` utils).
5. Captcha is actually enforced on the portal apex (Task 7: request without token → 400).

## P2 Portal skeleton

### Task 5: `schema/portal.ts`

`portalSession` (Better Auth session columns, no `activeOrganizationId`), `portalCompany`
(unique tenantId+cardCode), `portalMember` (PK companyId+userId, unique tenantId+userId). Invitation
and domain tables wait for P3. `bun run db:push`.

### Task 6: Portal Better Auth instance + entrypoint

`apps/server/src/portal/{auth.ts,index.ts}`: `session.modelName: "portalSession"`, cookie prefix +
zone, captcha, verification/reset via `authMail` branded by `t`, Microsoft `xms_edov` mapper.
Scripts `start:portal`, root `dev:portal-server`/`dev:portal`.

### Task 7: Portal builders + router (`me`, `lobby`, `branding`)

`apps/server/src/portal/orpc/{base.ts,router.ts}`. Builders per spec §4.3; `me` resolves state
itself (`internal` / company / null), like the internal `me`. Tests: own-table sessions, no cross-zone
cookie, captcha 400, builder refusals, `me` states, lobby.

### Task 8: `apps/portal` SPA

Vite (:5174) + TanStack Router + UI5. Apex: `/login`, `/signup`, `/forgot-password`,
`/reset-password`, `/` lobby. Tenant: `_authed` shell (NavigationLayout, ShellBar with tenant
name/logo, user menu: theme, density, switch supplier, sign out), Home, `/onboarding` (no company /
internal member). Turnstile widget. Shared: `AuthLayout` (brand slot), `SocialButtons`, host helpers,
appearance hook from `packages/ui`.

- [ ] Typecheck all projects, all tests, both builds, smoke the running stack; CLAUDE.md + spec
  status; commit "P2"; progress report.
