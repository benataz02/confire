# One SAP cache Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Everything Confire keeps from SAP lives in one `sap_cache` table behind one module, the model's
price list is cached from a stored SQL query, and the old cache tables, columns, maps and `pricing.itemTable` are gone.

**Architecture:** `packages/db` gets the table (`seq 0` = the entry, `seq ≥ 1` = a many-row entry's rows)
and `apps/server/src/sap-cache.ts` is its only reader and writer: a read-through for one-value kinds, a
streaming fill with a change hash for many-row kinds, a row read, a SQL header fragment for list queries,
and `forget`. Each existing cache moves onto it in its own task and drops its old storage in the same task,
so every task ends green; the last task generates the drop migration and sweeps docs and comments.

**Tech Stack:** Bun, TypeScript, drizzle-orm (node-postgres), Postgres 17, oRPC v2 beta, bun:test.

**Spec:** `docs/superpowers/specs/2026-11-09-sap-cache-design.md`

## Global Constraints

- Bun only. Tests run from the repo root (`bun test apps/server/test/<file>`), so the root `bunfig.toml` preload drops the API keys. Postgres must be up (`DATABASE_URL` in `.env`).
- No backwards compatibility: no data migration, no dual reads, no fallback to the old storage.
- `apps/server/src/sap-cache.ts` is the only `src` module that imports `sapCache`. Tests may read the table directly to assert deletions.
- Every timestamp the cache writes comes from the JS clock (`new Date()`), never SQL `now()`. Freshness compares against `Date.now()`, so `setSystemTime` in tests moves both.
- Lifetimes: `schema` until Refresh or older than `PARSER_EPOCH`; `entity_list` 24 h; `beas_schemas` 24 h; `currency` forever; `open_counts` 10 min; `print_layout` 2 h; `masterdata` the masterdata's `query.syncMinutes` (absent = manual only); `price_list` 24 h; `report` until the next run.
- The company rule: an entry is written with the company the SAP call carried. A read treats a seq-0 row whose `company` is distinct from `sap_connection.company_db` as absent, using `is not distinct from`, so a null company matches a tenant with no company or no `sap_connection` row.
- Price-list SQL, exactly: `SELECT ItemCode, Price FROM ITM1 WHERE PriceList = <n> ORDER BY ItemCode`. Code: `CF_PL_` + the first 8 hex digits of the sha1 of that text.
- Imports carry explicit `.ts` extensions, and `verbatimModuleSyntax` is on (`import type`).
- Keep every verified B1 error string and every comment that explains *why*. Mark a deliberate limit with `// ponytail:` and name its ceiling.
- Dev schema sync after each schema edit: `bun run db:push --force`. `--force` approves the drops; push otherwise prompts.
- Type-check is per project: `bunx tsc -p <project>/tsconfig.json --noEmit` for `apps/server`, `apps/app`, `apps/portal`, `packages/{db,b1,config-engine,ui}`.
- Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A tenant with no company.** In dev, before an agent reports one, or with no `sap_connection` row at all, an entry written with `company: null` must read back rather than look absent forever. Pinned in Task 1.
2. **A refill of the old company landing after a switch.** `rows()` must not serve its rows, and `entry()` must not serve its header. Pinned in Task 1.
3. **Two processes filling the same entry at once** (staff and portal). Both must finish, with no primary-key error, leaving exactly one set. Pinned in Task 1.
4. **HANA upper-cases column names** (`ITEMCODE`, `PRICE`) and may send the price as a string. A price must still be read. Pinned in Task 6.
5. **An empty price list.** It is an answer, not an error: zero rows, no `error`, `fetchedAt` set, and the BOM lines `unpriced`. Pinned in Task 6.

  ```ts
  export type Tx = Parameters<Parameters<typeof db.transaction>[0]>[0];
  export type CacheEntry<T = unknown> = { data: T | null; company: string | null; fetchedAt: Date | null; error: string | null };
  export type RowsHeader = { rows: number; hash: string; changedAt: string }; // seq-0 data of a many-row entry
  export const PARSER_EPOCH: number;                          // moved verbatim from entity-meta.ts
  export const LIFETIME_MS: Record<CacheKind, number | null>; // null = no clock: forever, until the next run, or per entry
  export function isFresh(kind: CacheKind, e: CacheEntry | null, lifetimeMs?: number | null): boolean;
  export function entry<T>(tenantId: string, kind: CacheKind, key: string): Promise<CacheEntry<T> | null>;
  export function put(tenantId: string, kind: CacheKind, values: { key: string; data: unknown }[],
    o: { company: string | null; fetchedAt?: Date }, tx?: Tx): Promise<void>;
  export function fail(tenantId: string, kind: CacheKind, key: string, company: string | null, error: unknown): Promise<void>;
  export function cached<T>(tenantId: string, kind: CacheKind, key: string,
    load: () => Promise<{ company: string | null; data: T }>, o?: { refresh?: boolean; lifetimeMs?: number | null }): Promise<T>;
  export function fill(tenantId: string, kind: CacheKind, key: string, company: string | null,
    pages: AsyncIterable<Record<string, unknown>[]>): Promise<{ rows: number; changed: boolean }>;
  export function rows(tenantId: string, kind: CacheKind, key: string, q?: RowQuery): Promise<Record<string, unknown>[]>;
  export function header(tenantId: string, kind: CacheKind, key: SQL): {
    data: SQL<unknown>; fetchedAt: SQL<Date | null>; error: SQL<string | null>; rows: SQL<number | null>; changedAt: SQL<Date | null> };
  export function forget(tenantId: string, o?: { kind?: CacheKind; keys?: string[] }, tx?: Tx): Promise<void>;
  ```
  `RowQuery` is imported as a type from `./lookups.ts`, unchanged.
