# Portal P3 Implementation Plan: Invites & companies

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Existing-BP invitations end to end. An internal admin invites from the BP Object Page, the
invitee accepts on the portal, and owners manage colleagues. Also auto-join by a registered email
domain and the Portal → Invitations list. Spec §15 P3.

**Architecture:** Two new tables (`portal_invitation`, `portal_company_domain`) and one shared
server module, `apps/server/src/portal/members.ts`. It holds every write to `portal_member`,
`portal_company_domain` and `portal_invitation`, and both processes import it, so the internal
router and the portal router enforce the same guard. Internal UI is a header action and a template
section on the declared `businessPartners` feature, plus a local List Report. The portal gets an
accept page, auto-join in `/onboarding`'s `beforeLoad`, and an owner-only `/company` page.

**Tech Stack:** Bun, Hono, oRPC, Better Auth 1.7.7, Drizzle/Postgres (node-postgres), React 19 +
UI5 Web Components + TanStack Router/Query, React Email + Resend.

**Spec:** `docs/superpowers/specs/2026-10-07-portal-redesign.md` (§4.2, §4.4, §5.1, §5.2, §9, §10, §11).

## Global Constraints

- `addPortalMember(tx, …)` is the **only** code that inserts into `portal_member` (spec §4.2).
- The tenant boundary stays host → tenant → membership/seat join. Internal handlers fence every
  company read by `portal_company.tenantId = context.tenantId`, portal handlers by the host tenant.
- Invitation link: `https://<slug>.portal.<domain>/accept/<invitationId>`, `expiresAt` = 14 days.
  Idempotency key `invite/<invitationId>`. One open invitation per (tenant, lower(email)) is enforced
  by a partial unique index.
- Free-mail domains never auto-join and are never registered. The list lives in code.
- Domains are written only by internal users (an invitation's `registerDomain`, or the BP Portal
  section), never by a portal call (spec §4.2).
- D24: a company owner invites only addresses on the company's registered domains, and never with
  `registerDomain`.
- Internal senders are admins/owners (`adminProcedure`), enforced on the server.
- **Decided with the user 2026-10-16:**
  - No `joined` audit event in P3. `portal_member.createdAt` and the accepted invitation are the
    record; P4 decides where `joined` lives (`ponytail:` note).
  - **Last-owner guard on both sides.** No change (role or removal), internal or portal, may leave a
    company that had an owner with none.
  - The company owner sees their company's pending invitations on `/company` and may cancel them
    (`company.members.cancelInvite`).
  - Invitation mail `Reply-To` is the inviter's email until P7's `portal_settings.replyTo`.
- Per-project typecheck: `packages/{b1,config-engine,db,ui}`, `apps/{agent,server,web,portal}`.
- No new dependencies.

## Review Focus

1. **An expired invitation must not block a re-invite forever.** It stays `pending` in the table,
   and the partial unique index would refuse the next send. → `sendInvitation` cancels this email's
   expired pending invitations before it inserts (test in Task 2).
2. **Email case.** An invite to `Anna@Kunde.de` is accepted by a user who signed up as
   `anna@kunde.de`, and the guard finds a seat whatever the case (Task 2/4 tests).
3. **Two owners demote each other at the same time.** At least one owner remains, because
   `changeMember` locks the company's owner rows `FOR UPDATE` (Task 2 test, `Promise.all`).
4. **Double accept, or accept after cancel.** Exactly one seat, and the loser gets `CONFLICT`
   (Task 4 test).
5. **Auto-joined first, then the invitation link.** A colleague who opened the portal root first
   (auto-join as `viewer`) and then clicks their `buyer` invitation ends up `buyer`, not stuck at
   "already a member". Accepting into your own company never lowers your role (Task 2/4 test).

### Task 1: Schema: `portal_invitation`, `portal_company_domain`

**Files:** Modify `packages/db/src/schema/portal.ts`.

**Produces:** `portalInvitation`, `portalCompanyDomain`, `PortalInviteStatus`, `PORTAL_ROLES`.

```ts
export const PORTAL_ROLES = ["owner", "buyer", "viewer"] as const;
export type PortalRole = (typeof PORTAL_ROLES)[number];
export type PortalInviteStatus = "pending" | "accepted" | "canceled";

/** Spec §4.2/§5. `companyId` null = a new-client invitation (P6) until its submit sets it. The random
 *  id is the link token; holding it is not enough, acceptance also checks the email (§5.2). */
export const portalInvitation = pgTable("portal_invitation", {
  id: uuid("id").primaryKey().defaultRandom(),
  tenantId: text("tenant_id").notNull(),
  companyId: uuid("company_id").references(() => portalCompany.id, { onDelete: "cascade" }),
  email: text("email").notNull(),
  role: text("role").$type<PortalRole>().notNull(),
  invitedBy: text("invited_by").references(() => user.id, { onDelete: "set null" }),
  registerDomain: boolean("register_domain").notNull().default(false),
  status: text("status").$type<PortalInviteStatus>().notNull().default("pending"),
  expiresAt: timestamp("expires_at", { withTimezone: true }).notNull(),
  createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),
}, (t) => [
  // "One open invitation per email per tenant" as a constraint: two concurrent sends cannot both win.
  uniqueIndex("portal_invitation_pending_uq").on(t.tenantId, sql`lower(${t.email})`).where(sql`status = 'pending'`),
  index("portal_invitation_company_idx").on(t.companyId),
]);

/** The auto-join index (§4.4). PK (tenantId, domain) is what stops one domain mapping to two companies. */
export const portalCompanyDomain = pgTable("portal_company_domain", {
  tenantId: text("tenant_id").notNull(),
  domain: text("domain").notNull(),
  companyId: uuid("company_id").notNull().references(() => portalCompany.id, { onDelete: "cascade" }),
  addedBy: text("added_by").references(() => user.id, { onDelete: "set null" }),
  addedAt: timestamp("added_at", { withTimezone: true }).notNull().defaultNow(),
}, (t) => [primaryKey({ columns: [t.tenantId, t.domain] }), index("portal_company_domain_company_idx").on(t.companyId)]);
```

```ts

/** The only insert into portal_member. Refuses staff of the tenant (FORBIDDEN); a seat at another
 *  company here → CONFLICT naming it. A second way into the SAME company never lowers the role. */
export async function addPortalMember(tx: Tx, m: { tenantId: string; companyId: string; userId: string; role: PortalRole }): Promise<void>;
/** Registers `domain` to the company: "added", "free" (free-mail, nothing written), or the CardCode it already belongs to. */

export async function changeMember(c: { tenantId: string; companyId: string; userId: string; role: PortalRole | null }): Promise<void>;
/** Guard (§5.1 existing-BP) → cancel this email's expired pending invitations → insert → mail after

  inviter: { id: string; name: string; email: string };

export async function cancelInvitations(tenantId: string, ids: string[], companyId?: string): Promise<number>;
```

Unique violations are recognised by Postgres code `23505` plus the constraint name. The code may
sit on the error itself or on `cause` (drizzle 0.45 wraps it in `DrizzleQueryError`), so read both:

```ts
const violated = (e: unknown, constraint: string) => {
  for (let x: any = e; x; x = x.cause) if (x.code === "23505" && x.constraint === constraint) return true;
  return false;
};
```

`addPortalMember` upsert, so a second way in raises the role at most and never lowers it:

```ts
await tx.insert(portalMember).values(m).onConflictDoUpdate({
  target: [portalMember.companyId, portalMember.userId],
  set: { role: sql`case when excluded.role = 'owner' or (excluded.role = 'buyer' and ${portalMember.role} = 'viewer') then excluded.role else ${portalMember.role} end` },
});
// 23505 on portal_member_tenant_user_uq → CONFLICT "You already belong to another company on this portal"
```

`portal-mail.tsx`: `PortalInvitation({ brand, inviterName, companyName, url, expiresAt })` in the

tenant name, `replyTo` = the inviter's email, `idempotencyKey: invite/<id>`. Brand =
`organization.name`/`logo`.
